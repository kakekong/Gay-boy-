# 06 — AI Logic Design

> All AI features live in `backend/app/ai/`. The code is split between **deterministic scoring** (sklearn / rule-based) and **LLM** (OpenAI / Claude) so that each capability is testable and explainable.

---

## 6.1 Lead Scoring AI

**Goal:** for every customer in `lead`/`presentation`/`engineering` stage, predict probability of becoming a closed-won deal in the next 90 days.

**Features (deterministic, transparent):**

| Feature | Source | Weight (initial heuristic) |
|---|---|---|
| `industry_baseline` | conversion rate of customer's industry historically | 0.20 |
| `response_speed_hours` | avg sales-to-customer round-trip time (last 30d) | 0.15 |
| `follow_up_consistency` | activities/week stddev (lower=better) | 0.10 |
| `project_value_log` | log10(quotation_amount or expected) | 0.20 |
| `historical_conversion` | this PIC's previous deals' win rate | 0.15 |
| `engagement_breadth` | distinct contact persons interacted with | 0.10 |
| `pipeline_velocity` | days_in_stage vs industry median (inverse) | 0.10 |

**Pipeline:**
1. Featurize → `LeadScorer.transform(customer)`
2. Predict via logistic regression model trained on historical labeled data (won=1, lost=0).
3. Output:
   ```json
   {
     "score": 0..100,
     "drivers": [{"feature":"response_speed_hours","contribution":+12}, ...],
     "recommended_action": "Schedule technical meeting within 5 days"
   }
   ```
4. Recommended action is generated by a **rule layer** mapped from the top driver, with LLM polishing only the wording.

> If no labeled data is yet available (cold start), use the heuristic weights above and switch to learned model once `n_won + n_lost >= 50`.

## 6.2 Auto Quotation AI

**Input:** structured form
```json
{
  "customer_id": "...",
  "industry": "cement",
  "items": [
    { "intent": "Replacement chain conveyor 12 inch", "qty": 200, "uom": "m" },
    { "intent": "Custom transition chute", "spec": "carbon steel, 3mm" }
  ],
  "deadline": "2026-08-01",
  "payment_terms_pref": "termin 30/40/30"
}
```

**Pipeline:**
1. **Item resolution** — embedding search against `products` master and prior `quotation_items` to detect standard parts.
2. **Pricing logic:**
   - standard: `list_price * qty * (1 - default_discount[customer.tier])`
   - custom: cost engine = `material_cost(spec) + labor_estimate(complexity) + margin_target(industry)`
3. **LLM compose** — produce notes, scope, exclusions, T&Cs (short or detailed variant).
4. **Output:** quotation draft (status=`draft`) + suggestion line items + suggested validity & payment terms.

**Prompt skeleton (compose step):**

```
SYSTEM: You are a senior quotation engineer for an Indonesian project-based industrial supplier.
Write a {variant} quotation in Bahasa Indonesia (formal, technical) for the customer below.
Include: scope of work, line items, pricing, payment terms, delivery time, exclusions, validity.

CONTEXT:
- Customer: {{company_name}} ({{industry}})
- Past projects: {{kb_summary}}
- Items resolved: {{resolved_items_json}}

RULES:
- Never promise lead time shorter than {{min_lead_time}} days.
- If item is custom, mark it CUSTOM and note that drawing approval is required.
- If discount > 5%, mark "Pending approval".
```

## 6.4 Deal Risk Detector

**Features:**
| Feature | Definition |
|---|---|
| `days_since_last_activity` | now - max(activity.occurred_at) |
| `customer_response_lag` | EMA of inbound→outbound delays in last 30d |
| `quote_revisions` | count(quotation versions for this deal) |
| `discount_drift` | (current discount) - (initial discount) |
| `activity_below_threshold` | activities/week < industry baseline |
| `similar_lost_pattern` | cosine similarity to embeddings of prior lost deals |

**Risk score:** weighted sum mapped to bands:
- `low` < 0.35
- `medium` 0.35–0.65
- `high` ≥ 0.65

**Output stored in `deal_risks`:**
```json
{
  "risk_level": "high",
  "reasons": [
    {"factor":"days_since_last_activity","value":8,"contribution":+0.30},
    {"factor":"discount_drift","value":0.07,"contribution":+0.18}
  ],
  "recommended_action": "Follow up within 24h; offer revised pricing 7%."
}
```

Recommended actions are picked from a fixed catalog so the UI can render them as one-click buttons.

## 6.5 Profit Intelligence Engine

**Inputs per project:**
- `quotation.total` (revenue) and committed cost lines from `project_costs`
- live updates as POs and DOs are processed

**Calculations:**
- `cost_actual = Σ project_costs.amount`
- `cost_estimate = Σ initial_estimates`
- `margin_estimate = (revenue - cost_estimate) / revenue`
- `margin_actual = (revenue - cost_actual) / revenue`
- breakdown: material / purchasing / logistics / labor / discount

**AI overlay:**
- threshold breach (default `margin_actual < margin_estimate - 5pp`) → alert
- LLM action suggestions:
  - "Increase price on next variant"
  - "Switch supplier (see supply risk)"
  - "Reduce courier tier"

## 6.6 Smart Reminder Engine (AI timing)

For each `(customer, sales_pic)`:
1. Build a **responsiveness profile** from historical activities:
   - hourly histogram of inbound replies
   - day-of-week distribution
   - average reply lag bucket
2. For each reminder, compute optimal-time score:
   `score(t) = P(reply | hour) * P(reply | dow) * recency_decay`
3. Pick `argmax t in next 48h` → `reminder.ai_optimal_at`.
4. Reorder per-sales daily Top Actions by:
   - deal value
   - risk level
   - time-sensitivity
   - SLA breach proximity

## 6.7 Opportunity Expansion AI (Upsell)

For each customer with completed projects:
- Build "next-likely-need" list using:
  - product co-occurrence (market basket on `quotation_items`)
  - usage cycles (industry knowledge, e.g. chain replacement ~ every 12–18 months in cement)
  - similar-customer behavior (cosine on customer embedding)
- Output: `[{product, reason, suggested_window, suggested_message}]`

## 6.8 Document Intelligence (Auto Parser)

Pipeline:
```
input (pdf/image/text)
   → if pdf with text layer: pdfminer
   → else OCR (tesseract / Vision-LLM fallback)
→ normalize text
→ LLM extract (function-calling JSON schema)
→ confidence per field (LLM self-rated + heuristic checks)
→ if confidence < 0.7 → human review queue
→ else commit (project / quotation_draft / activity)
```

**LLM extraction schema (function call):**
```json
{
  "name": "extract_po",
  "parameters": {
    "type": "object",
    "properties": {
      "customer_company": {"type":"string"},
      "po_number": {"type":"string"},
      "po_date": {"type":"string","format":"date"},
      "delivery_address": {"type":"string"},
      "items":[{"type":"object","properties":{
         "description":{"type":"string"},"qty":{"type":"number"},
         "uom":{"type":"string"},"unit_price":{"type":"number"}}}],
      "payment_terms":{"type":"string"},
      "deadline":{"type":"string","format":"date"}
    },
    "required":["po_number","items"]
  }
}
```

## 6.9 Loss Analysis AI

- Each `closed_lost` deal must specify `lost_reason` (categorical + free text).
- Nightly job clusters `(industry, lost_reason, response_lag, price_diff)` and emits patterns:
  > "You lose 70% deals in mining when first response > 2 days."
- The output is shown on the Executive Dashboard and used to seed the AI Sales Coach.

## 6.10 Sales Performance AI Coach

For each sales user, weekly:
- Aggregate KPIs (own pipeline) vs team / personal-best.
- Compare patterns of closed-won vs closed-lost (their own).
- Generate a 3-bullet coaching note:
  - "Your follow-up frequency dropped 40% on cement deals."
  - "Try shorter quotation variant for first contact — your win rate is 22% higher with short."
  - "Schedule technical meetings earlier — the won deals had it within 7 days vs 14 for lost."

## 6.11 Auto Workflow Orchestrator

A small rule engine (`ai/orchestrator.py`) reacts to domain events:

| Event | Action |
|---|---|
| `quotation.won` | create project, copy items, kick off purchasing if needed |
| `document.parsed.po` | create project, notify ops, link customer |
| `payment.overdue.t7` | WA reminder + flag at-risk |
| `drawing.revision_requested` | reopen engineering task, notify sales |
| `gr.qc.failed` | open supplier issue, notify purchasing |

These are not LLM rules — pure code, but exposed in the AI Command Center because the user perceives them as "the AI doing things automatically".

## 6.12 Supply Risk Monitor

Per supplier, weekly:
- `lead_time_delay = avg(actual_delivery - po_date) - quoted_lead_time`
- `qc_fail_rate = qc_fail / qc_total`
- `price_volatility = stddev(unit_price last 6 mo)`

Compose risk score, highlight worst, **suggest alternative supplier** by:
- same product category
- best (low risk, comparable price)

## 6.13 Knowledge Base AI (Company Memory)

Stored as embeddings in `embeddings` (pgvector):
- past projects' scope & lessons learned
- engineering solutions
- customer preferences (e.g. "PT X always rejects galvanized; uses SS304")

Used by:
- Auto Quotation (as `kb_summary`)
- Sales Assistant (closing strategy context)
- Executive dashboard search ("show all projects with chain conveyor in cement")

Indexing pipeline:
1. on event (`project.closed`, `drawing.approved`, `lessons.added`) → enqueue
2. worker: chunk text → embed (`text-embedding-3-large` or local) → upsert
3. retrieval: top-k cosine + rerank (LLM optional) → return excerpts

---

## 6.14 Model & cost guardrails

- All LLM calls go through `ai/llm.py` with:
  - request retry (max 3, exp backoff)
  - cost log per call (model, prompt_tokens, completion_tokens, IDR cost)
  - PII redaction filter before sending (phone numbers normalized, no API keys)
  - per-tenant monthly cap (env var `AI_BUDGET_IDR_MONTH`)
- Fallback to local templates when LLM unavailable so the system remains functional.
